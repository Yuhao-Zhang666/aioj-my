# RAG 方向下一步功能及规划

> 更新时间：2026-09-02
>
> 本文针对 AIOJ 当前已经具备的 Embedding、对话检索、长期记忆和学习画像能力，规划题库 RAG 的下一步实现。文中区分当前应立即实现的功能、后续阶段和暂不承诺的能力。

## 一、总体目标

将经过审核的 AIOJ 题库内容建设为可检索、可推荐、可用于 AI 出题和教学辅导的知识资产。

题库 RAG 的核心链路是：

```text
教师/学生自然语言需求
  -> 题目候选召回
  -> 权限、可见性和生命周期过滤
  -> 关键词、向量、标签和难度混合排序
  -> 返回结构化题目摘要和匹配原因
  -> 需要时回取授权题目详情
```

题库 RAG 不直接替代现有题库搜索、推荐或 AI 出题流程，而是作为统一的语义召回层，为这些功能提供候选题目。

## 二、当前基础与边界

### 已有基础

- `AiRetrievalService` 已支持 Embedding、余弦相似度、关键词降级、时间和来源加权；
- `ai_retrieval_chunks` 已支持向量、内容哈希、题目 ID、算法 Key、画像 Key 和敏感级别；
- 当前部署已启用 DashScope `text-embedding-v3`，使用独立 Embedding 配置；
- AI 对话已具备摘要检索、原文取证、短期上下文压缩和长期记忆；
- AIOJ 已有题目标签、难度、题面、题目状态、审核和归档机制；
- Tutor 推荐和学习画像已经具备可接入的业务基础；
- AI 出题已经具备结构化生成、静态检查、沙箱验证、自动修复和教师审核流程。

### 当前明确边界

- 题目本身尚未完成统一的批量 Embedding 和增量索引闭环；
- 当前语义检索主要服务对话摘要、提交分析和画像证据；
- AI 出题流程目前尚未接入历史题目的 RAG/Few-shot 检索；
- 题库 RAG 不应索引完整标准解、隐藏测试、参赛者源码和完整判题日志；
- Embedding 失败不能阻塞题目发布、修改和正常题库业务；
- 题库权限和题目可见性必须由服务端判断，不能依赖模型或前端传入的题目 ID。

## 三、当前要实现的第一批功能

第一批目标是完成“题目可索引、可查询、可验证”的最小闭环，不立即扩展复杂 GraphRAG 或多 Agent 编排。

### 1. 题目索引模型和准入规则

建立题目进入 RAG 索引的明确规则：

- 只索引公开、已审核、未归档、允许当前用户访问的题目；
- 草稿题、私有题、删除题、违规题不进入普通题库召回；
- 题目修改后按照内容哈希判断是否需要重新索引；
- 归档、删除和恢复必须同步更新索引状态；
- 每条索引记录保留题目版本、模型版本、内容哈希和更新时间。

建议补充的索引状态字段：

```text
problem_id
content_hash
index_status       PENDING / READY / FAILED / BLOCKED
index_version
embedding_model
embedding_dimension
indexed_at
last_error
```

### 2. 题目检索文本构建

不直接将完整题目原文无差别送入 Embedding，而是生成安全、稳定的检索文本：

```text
标题
题面摘要
输入输出特征
知识点
算法标签
数据范围和复杂度要求
难度信息
适用课程或训练阶段
```

不进入普通题库向量的内容：

- 完整标准解代码；
- 完整参考解代码；
- 隐藏测试数据；
- 参赛者提交源码；
- 完整内部判题日志；
- 未审核题目草稿；
- 其他无关用户数据。

### 3. 现有题库批量索引

实现一次性批量索引任务：

```text
读取符合准入条件的题目
  -> 清洗和生成检索文本
  -> 计算内容哈希
  -> 调用 Embedding
  -> 写入 ai_retrieval_chunks
  -> 记录成功、失败和跳过统计
```

要求：

- 任务可重复执行并保持幂等；
- 支持分批处理和失败重试；
- 支持并发上限和 Embedding 容量控制；
- 单题失败不影响其他题目；
- 任务结束提供成功数、失败数、跳过数和耗时；
- 可按题目范围、更新时间或索引状态重新执行。

### 4. 通用题库语义检索 API

阶段二的产品形态应定义为“通用题库语义检索服务”，首个可见入口优先面向学生，但底层 API 同时服务教师和 AI 出题。

建议接口：

```text
GET /api/v1/problems/semantic-search
```

建议参数：

```text
query
difficulty
algorithm
knowledgeNode
courseId
limit
mode = KEYWORD / SEMANTIC / HYBRID
```

返回内容：

- 题目 ID、标题、难度和标签；
- 题目可见性和当前状态；
- 匹配分数；
- 匹配原因；
- 相关知识点和算法；
- 题目详情深链；
- 是否发生 Embedding 降级。

权限过滤必须在召回结果返回前完成。模型只能获得当前用户有权看到的题目摘要。

### 5. 学生端自然语言搜题

首个产品入口建议放在学生端 Problems 页面，支持：

- “找几道适合初学者的 BFS 题”；
- “推荐和区间合并类似但更难的题”；
- “我想练习前缀和的边界处理”；
- “找一道适合复习二分查找的基础题”。

学生侧重视结果可读性和跳转效率，返回题目卡片、匹配理由和练习入口，不暴露内部向量分数细节。

### 6. 增量索引

题目生命周期变化必须触发增量索引：

```text
新建/发布题目 -> 创建索引
修改题面/标签/难度 -> 内容哈希变化，重新索引
归档题目 -> 停止召回或标记 BLOCKED
恢复题目 -> 重新进入索引队列
删除题目 -> 删除或废弃索引
Embedding 失败 -> 保留 FAILED，异步重试
```

索引更新不得阻塞题目主业务。题目发布成功与向量索引成功应是两个独立状态。

## 四、分阶段规划

### 阶段一：题目准入、批量建索引和运行保障

**目标：** 让现有题库安全、稳定地进入可检索状态。

主要工作：

1. 确定题目索引文本和脱敏规则；
2. 定义公开/审核/归档等索引准入条件；
3. 实现题目批量 Embedding 任务；
4. 补充索引状态、内容哈希和失败记录；
5. 增加新增、修改、归档、恢复和删除的增量索引；
6. 增加并发控制、重试、幂等和任务观测；
7. 确认 Embedding 故障不阻塞题目发布。

验收标准：

- 现有符合准入条件的题目均可批量进入索引；
- 重复执行不会产生重复向量记录；
- 修改题面后旧索引不会继续作为最新结果；
- 私有、归档和删除题目不会错误出现在学生结果中；
- Embedding 服务异常时题库基本功能仍可用。

### 阶段二：通用语义检索服务和学生端入口

**目标：** 让学生可以用自然语言查找题目，同时形成后续能力共用的后端检索层。

主要工作：

1. 实现题库语义检索服务；
2. 支持关键词、语义和混合检索模式；
3. 增加难度、算法、知识点和课程过滤；
4. 增加服务端权限和题目状态过滤；
5. 在学生端 Problems 页面接入自然语言搜索；
6. Embedding 不可用时降级到关键词和结构化过滤；
7. 返回匹配原因和可访问题目深链。

这一阶段虽然首个业务入口面向学生，但 API 必须设计成通用能力，后续可被以下模块复用：

```text
学生自然语言搜题
教师题库检索和组卷
相似题/重复题检测
AI 出题 RAG
Tutor 个性化推荐
```

### 阶段三：教师检索、组卷和相似题检测

**目标：** 服务教师备课、组卷和题库治理。

主要工作：

- 按课程、知识点、算法和难度筛选题目；
- 根据自然语言生成候选题集；
- 支持入门题、巩固题、变式题和综合题的梯度组卷；
- 检测题面、标题、输入输出结构和知识点的相似度；
- 标记 `POSSIBLE_DUPLICATE` 和 `MANUAL_REVIEW_REQUIRED`；
- 展示相似题及其匹配原因；
- 支持教师确认误报和保留合理变式题。

相似题检测只能作为审核辅助，不自动删除题目或直接阻止发布。

### 阶段四：个性化推荐接入

**目标：** 将题库 RAG 与学习画像、提交分析和 Tutor 推荐结合。

推荐链路：

```text
学生学习画像/近期错误
  -> 提取弱点知识点和算法
  -> 题库 RAG 召回候选
  -> 过滤已完成、重复和无权限题目
  -> 按难度梯度和多样性重排
  -> 生成推荐理由
  -> 返回题目深链
```

推荐结果应保存：

- `recommendationId`；
- `learningContextId`；
- 推荐规则或模型版本；
- 题目 ID 和推荐理由；
- 签发时间和过期时间；
- 是否已开始、完成和通过。

阶段四的效果指标包括推荐点击率、开始率、完成率、通过率和推荐后的重复提交改善情况。

### 阶段五：接入 AI 出题 RAG

**目标：** 让 AI 出题参考经过审核的历史题目，同时降低重复题和失配题风险。

工作流：

```text
教师出题需求
  -> 检索相似历史题和相关知识点
  -> 生成相似题摘要、差异要求和禁止复制约束
  -> 生成结构化设计规划
  -> 生成题面、标程和测试材料
  -> 相似题/重复度检查
  -> 静态验证
  -> 沙箱验证和交叉验证
  -> 自动修复
  -> 教师审核和导入
```

检索结果进入出题模型时应采用最小化原则：

- 只提供少量高相关候选；
- 优先提供题目摘要和结构化字段；
- 不提供隐藏测试和无关代码；
- 明确要求生成题目与参考题存在可解释差异；
- 保留候选题来源和相似度，写入出题审计快照。

该阶段必须建立在阶段一至四的权限、索引一致性和检索质量基础上，不能仅通过把题面拼接进 Prompt 的方式实现。

### 阶段六：课程级题单和训练任务生成

**目标：** 从单题检索扩展到可交付的训练方案。

教师或学生可以指定：

- 课程章节；
- 知识点范围；
- 起始和目标难度；
- 题目数量；
- 预计训练时长；
- 是否强化近期薄弱点；
- 是否排除已完成题目。

系统交付：

- 有顺序的题目清单；
- 每道题的训练目标；
- 难度梯度；
- 推荐理由；
- 预计先修知识；
- 可直接进入 AIOJ 练习的深链。

### 阶段七：知识图谱和 GraphRAG 融合

**目标：** 在题库 RAG 稳定后，引入知识点关系、先修关系和题目-知识点图谱。

可支持：

- 根据先修知识自动补齐训练路径；
- 发现知识点之间的迁移关系；
- 解释一道题覆盖的多个知识点；
- 结合学生掌握度规划下一步学习节点；
- 将向量相似度和图关系召回融合。

该阶段属于增强方向，不应作为题库 RAG 第一版上线前置条件。

## 五、统一检索排序策略

推荐采用混合排序：

```text
基础相关性
  = 语义相似度
  + 关键词匹配
  + 标题/标签命中

业务重排
  = 难度匹配
  + 知识点匹配
  + 算法匹配
  + 课程范围
  + 用户画像
  + 题目质量
  + 新鲜度
  - 已完成重复题
  - 低质量或待审核题
```

其中权限和生命周期过滤属于硬条件，不能通过排序分数补偿。题目不可见时必须在召回结果中完全移除。

## 六、数据和安全要求

### 数据分层

- 原始题目和题目状态：权威业务数据；
- 检索文本和向量：派生数据；
- 推荐理由和相似题报告：可重建业务结果；
- 题目审核和导入记录：审计事实。

原始题目变化后，应通过内容哈希或版本号使派生索引失效并重新构建。

### 权限要求

- 学生只可检索当前有权访问的题目；
- 教师检索范围必须受机构、课程和角色限制；
- 私有题和比赛限制题不得通过向量相似度泄露存在性；
- AI 出题只能使用授权的历史题摘要；
- 前端传入的 `problemId`、课程 ID 和用户 ID 不能作为最终授权依据。

### 隐私和内容控制

- 不索引密钥、Token、完整代码和原始隐藏输出；
- 不将 Embedding 向量直接暴露给模型或前端；
- 检索失败、降级和权限拒绝要保留可追踪日志；
- 生产日志不得记录完整 Prompt、隐藏测试或未脱敏源码。

## 七、测试和评估规划

### 功能测试

- 批量索引幂等；
- 内容修改触发重建；
- 归档、恢复和删除同步；
- Embedding 失败重试；
- 关键词降级；
- 学生、教师和跨机构权限隔离；
- 题目详情回取；
- 推荐结果深链和过期处理；
- 相似题检测误报处理。

### 检索质量测试

建立人工标注的查询集，覆盖：

- 同义表达；
- 中文算法术语；
- 口语化学习目标；
- 难度要求；
- 知识点组合；
- 题面近重复；
- 无结果查询；
- 权限边界查询。

重点指标：

- Recall@K；
- Precision@K；
- NDCG；
- 语义检索与关键词检索对比；
- 权限错误率；
- 归档题误召回率；
- Embedding 降级后的可用率。

### 出题 RAG 专项指标

- 历史题引用准确率；
- 相似题发现率；
- 生成题重复率；
- 题目设计与需求匹配率；
- 静态验证通过率；
- 沙箱验证通过率；
- 教师采纳率。

## 八、推荐实施优先级

```text
1. 题目准入和批量 Embedding
2. 题目增量索引和失败恢复
3. 通用语义检索 API
4. 学生端自然语言搜题
5. 教师检索、组卷和相似题检测
6. 学习画像驱动的个性化推荐
7. AI 出题 RAG
8. 课程级训练任务生成
9. 知识图谱/GraphRAG 融合
```

## 九、阶段性结论

题库 RAG 的第一阶段不是直接做“AI 自动出题”，而是先把题目内容、状态、权限和索引生命周期做可靠。第二阶段建设的是通用语义检索服务，首个用户入口面向学生，但底层能力必须同时支持教师和 AI 出题。只有当题目召回、权限过滤和索引一致性稳定后，才适合把题库 RAG 接入个性化推荐和 AI 出题流程。

最终目标是：

> 把教师和学生的自然语言需求转化为题库检索条件，把题库检索结果转化为可解释的推荐、训练方案和出题约束，再通过 AIOJ 的判题验证和人工审核完成结果闭环。
