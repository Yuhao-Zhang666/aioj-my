|---|---|---|

## 第 1 章 你需要会哪些技术（按"必须会 / 会用就行 / 暂时不用管"分级）

这是我读完两边代码后，按**完成任务一所需**的真实依赖排的。

|---|---|---|---|
| Java 17（record / Stream / Optional / 泛型） | 🔴 必须熟 | 全部 | 项目代码大量用 record 和 Stream，不熟读不动 |
| Spring Boot（IoC / 配置 / 事务） | 🔴 必须熟 | 全部 | 一切的基础 |
| MyBatis-Plus + SQL | 🔴 必须熟 | 索引表读写、批量查询 | 项目的数据访问全靠它 |
| MySQL 索引与查询优化 | 🟡 会用 | 为索引表设计字段和索引 | 你新增的表要能撑住全题库 |
| REST API 设计（Controller 层） | 🔴 必须熟 | 阶段三的语义检索接口 | 你要交的第一个对外接口 |
| **Embedding / 向量 / 余弦相似度** | 🔴 必须懂概念 | 检索核心 | **这是你全新的东西，也是本任务的技术核心** |
| 权限与可见性判断（ABAC 思想） | 🟡 会用 | 题目准入规则 | 任务书反复强调"权限过滤必须服务端做" |
| 单元测试（JUnit + Mockito） | 🟡 会用 | 验收标准靠它证明 | 项目已有测试可抄 |
| Redis | ⚪ 暂时不用 | — | 判题链路才用，RAG 第一阶段用不上 |
| RabbitMQ | ⚪ 暂时不用 | — | 同上 |
| React / 前端 | ⚪ 阶段二再碰 | 学生端搜题页 | 任务书阶段二才需要 |
| Docker | ✅ 你已会 | 跑本地环境 | 保持即可 |
| go-judge 沙箱 | ⚪ 完全不用 | — | 与本任务无关 |
| GraphRAG / 知识图谱 | ⚪ 远期 | 任务书阶段七 | 现在看纯属浪费时间 |

### 阶段 2：数据库与接口设计（第 5~6 周）

**学**：MySQL 索引与优化（网课 A3）
**练**：`problem-service` 的题目模块

| 周 | 学什么 | 练手的项目代码 |
|---|---|---|
| 5 | 表设计、主键/唯一键/联合索引、`EXPLAIN` 看执行计划 | `backend/api-contract/src/main/resources/db/migration/` 的建表 SQL |
| 6 | Flyway 迁移机制、分页查询、N+1 问题 | `problem-service` 的 `ProblemController` + `ProblemEntity` |

**这阶段你要能回答的核心问题**：

- 为什么 `ai_retrieval_chunks` 表建了 `UNIQUE KEY uk_ai_chunk_owner_hash (owner_type, owner_id, text_hash)`？它是干什么用的？
- 如果按 `problem_id` 查，现有索引够用吗？（提示：看 `V45__ai_retrieval_metadata.sql`）

> 💡 顺便理解一个工程规范：**这个项目用 Flyway 管理数据库变更**，你以后要加字段，必须新建一个 `V71__xxx.sql` 这样的文件，**绝不能直接改已有的迁移文件**（Flyway 会校验 checksum 然后拒绝启动）。当前最新迁移是 `V70`。

### 阶段 3：AI 与向量检索基础（第 7~9 周）★ 本任务的技术核心

**学**：Embedding 与 RAG 概念（网课 B1、B2）
**练**：读 `ai-service` 的检索代码

| 周 | 学什么 | 练手的项目代码 |
|---|---|---|
| 7 | 什么是 Embedding、向量、余弦相似度、为什么能"语义搜索" | 概念先搞懂，再动代码 |
| 8 | RAG 是什么：召回 → 过滤 → 重排 → 生成 | `backend/ai-service/src/main/java/com/aioj/next/ai/domain/AiRetrievalService.java` |
| 9 | 向量存储的几种做法（内存 / MySQL JSON / 专用向量库） | 同上，重点看 `searchDetailed` 和 `cosine` |

**`AiRetrievalService` 里你要看懂的三个方法**：

```text
indexChunk(...)      → 把一段文本变成向量存进 ai_retrieval_chunks
searchDetailed(...)  → 拿 query 算向量，和库里的向量比余弦相似度，排序返回
score(...)           → 除了相似度，还叠加了"同题目/同提交/算法匹配/时间新鲜"等加权
```

**看完必须能自己讲清楚**：

- 余弦相似度为什么能衡量"语义相近"？值域是多少？
- `searchDetailed` 里先 `LIMIT 200` 再在 Java 内存里算相似度——这样做有什么性能问题？（这是任务书阶段三要解决的）
- 为什么代码里要有"关键词降级"（推荐看 `semanticOrKeywordScore`）？

**动手练习**：写一个 20 行的小 Java 程序，自己调一次 Embedding 接口，算两个句子的余弦相似度，看数字是否符合直觉。

## 第 5 章 你的正式任务拆解：题库 RAG 第一阶段

任务书第一节到第三节是你要做的。我把它翻译成**能动手的步骤**。

### 5.1 先搞清"题目数据在哪、长什么样"

题目存在 `problem-service` 的 `problems` 表，实体是：

```text
backend/problem-service/src/main/java/com/aioj/next/problem/persistence/entity/ProblemEntity.java
```

字段（这是你构建检索文本的原料）：

```text
id, title, difficulty, statement, notes, tags,
timeLimitMillis, memoryLimitKb,
cpp/python/javaTimeLimitMultiplier,
aiGenerated, visibility, createdBy,
createdAt, updatedAt, deleted, archivedAt, deletedAt, deletedBy
```

**注意**：题目的**可见性/归档/删除状态**全在这里（`visibility`、`archivedAt`、`deleted`）。
任务书说"只索引公开、已审核、未归档、允许当前用户访问的题目"——判断依据就是这个实体的字段。

### 5.2 ⚠️ 一个老师文档没点明、但你一定会撞上的问题

这一步很重要，**请认真读**。

任务书建议的索引状态字段是：

```text
problem_id, content_hash, index_status, index_version,
embedding_model, embedding_dimension, indexed_at, last_error
```

而项目现在实际有的表（`V8` + `V45` 两个迁移建出来的 `ai_retrieval_chunks`）是：

```sql
id, user_id BIGINT NOT NULL,        -- ★ 注意这个 NOT NULL
owner_type, owner_id,
chunk_text, metadata_json, sensitivity,
problem_id, submission_id, contest_id, contest_run_id, contest_problem_id,
algorithm_key, profile_key,
embedding_model, embedding_dimension, embedding_json, text_hash,
created_at, updated_at,
UNIQUE KEY uk_ai_chunk_owner_hash (owner_type, owner_id, text_hash)
```

**冲突点有三个**：

| # | 问题 | 说明 |
|---|---|---|
| 1 | **`user_id NOT NULL`** | 这张表是**按用户隔离**设计的（存的是"某个学生的对话记忆/画像"）。而题库索引是**全体共享的知识**，不属于任何用户 |
| 2 | **唯一键含 `owner_id`** | 题库索引的唯一性应该按 `problem_id + content_hash` 判，不是 `owner_type/owner_id` |
| 3 | **缺 4 个字段** | `index_status`、`index_version`、`indexed_at`、`last_error` 表里都没有 |
| 4 | **没有 `user_id` 条件下的全表召回** | `searchDetailed` 第一行就是 `.eq("user_id", userId)`，题库检索不能这么写 |

**这意味着什么？**

> 你不能直接往 `ai_retrieval_chunks` 里塞题库索引，然后说"做完了"。
> 你必须**先做一个设计决策**，并和老师确认：

**方案 A：新建一张独立的表**（例如 `problem_retrieval_index`）
- 优点：不动现有表，语义清晰，题库索引和用户记忆彻底分开，`index_status` 等字段自然加上
- 缺点：要做一套新的 Mapper/Entity，检索代码要新写一份（但可以抄 `AiRetrievalService`）

**方案 B：扩展现有 `ai_retrieval_chunks`**
- 做法：把 `user_id` 改成可空（或用一个约定的"系统用户"ID），`owner_type = 'problem_index'`，新增 4 个字段
- 优点：复用现有检索逻辑，改动少
- 缺点：语义混乱（"题库知识"混在"用户记忆"表里），且**权限过滤逻辑容易出错**——一旦忘了按 `owner_type` 过滤，学生就可能召回别人的对话记忆。**这是安全事故**

> 🎯 **给你的建议：倾向方案 A。**
> 理由：任务书第六节明确要求"数据分层：原始题目是权威业务数据，检索文本和向量是派生数据"。
> 派生数据没道理和用户私有记忆挤在一张表里。而且 Agent Core V3 反复强调
> "摘要、索引和记忆都是派生数据"，边界清楚才能不犯错。
>
> **但这是架构决策，一定要拿去和老师确认，别自己拍板。**
> 顺便这也是你向老师展示"我认真读了文档并且发现了缝隙"的最好机会。

**建议的提问方式**（可以直接发给老师）：

> 老师，我读 `V8__ai_learning_context_memory.sql` 发现 `ai_retrieval_chunks` 的
> `user_id` 是 NOT NULL、唯一键是 `(owner_type, owner_id, text_hash)`，
> 这是按用户隔离的设计。题库 RAG 要的是全局共享索引，而且需要
> `index_status / index_version / indexed_at / last_error` 四个字段。
> 我倾向于新建一张 `problem_retrieval_index` 表，不动现有表，您觉得可以吗？

### 5.3 子任务拆解（按这个顺序做）

#### 子任务 1：题目检索文本构建（先写这个，最容易，也最该先确认）

任务书第二节规定检索文本包括：

```text
标题 / 题面摘要 / 输入输出特征 / 知识点 / 算法标签 /
数据范围和复杂度要求 / 难度信息 / 适用课程或训练阶段
```

**明确不能进去的**：标准解代码、隐藏测试数据、参赛者源码、内部判题日志、未审核草稿。

**你要写的东西**：一个纯函数，输入 `ProblemEntity`（+ 可能的标签），输出一段文本。

```text
例如：ProblemRetrievalTextBuilder.build(problem)
  → "标题：区间合并\n难度：中等\n知识点：排序、贪心\n标签：..."
```

**为什么先做这个**：
1. 它是纯逻辑，**可以完全用单元测试覆盖，不需要连数据库**
2. 它是**全文检索质量的地基**——文本构建得烂，后面向量再准也没用
3. 它是**最需要老师确认**的东西（哪些题面内容可以进索引，是安全决策不是技术决策）

**产出**：一个类 + 一组单元测试（覆盖：正常题、无标签题、超长题面、空题面）。

#### 子任务 2：批量索引任务（阶段一的核心）

任务书的流程：

```text
读取符合准入条件的题目
  -> 清洗和生成检索文本
  -> 计算内容哈希
  -> 调用 Embedding
  -> 写入索引表
  -> 记录成功、失败和跳过统计
```

**要求（任务书原文）**：

- 幂等：重复执行不产生重复记录
- 分批处理 + 失败重试
- 并发上限和 Embedding 容量控制
- **单题失败不影响其他题目**
- 结束输出成功数/失败数/跳过数/耗时
- 可按题目范围、更新时间或索引状态重新执行

**技术要点（读代码时注意）**：

- Embedding 怎么调？看 `ai-service` 的 `AiProvider` / `OpenAiCompatibleProvider`
- 容量控制？看 `AiCapacityService`（`AiRetrievalService` 注入了它）
- 幂等怎么做？看 `indexChunk` 里的 `text_hash` 查重逻辑
- 配置在哪？`backend/ai-service/src/main/resources/application.yml` 第 112~117 行：

```yaml
embedding:
  enabled: ${AI_EMBEDDING_ENABLED:true}
  base-url: ${AI_EMBEDDING_BASE_URL:https://dashscope.aliyuncs.com/compatible-mode/v1/embeddings}
  api-key: ${AI_EMBEDDING_API_KEY:}
  model: ${AI_EMBEDDING_MODEL:text-embedding-v3}
  dimension: ${AI_EMBEDDING_DIMENSION:1024}
```

> 💡 生产用 **DashScope `text-embedding-v3`，1024 维**。这个数字你要记住——
> `embedding_dimension` 字段要存它，换模型时是要整体重建索引的。

#### 子任务 3：准入规则与增量索引（阶段一收尾）

```text
新建/发布题目     -> 创建索引
修改题面/标签/难度 -> 内容哈希变化 -> 重新索引
归档题目          -> 停止召回 / 标记 BLOCKED
恢复题目          -> 重新进队列
删除题目          -> 删除或废弃索引
Embedding 失败    -> 保留 FAILED，异步重试
```

**最重要的约束（任务书原话）**：

> **索引更新不得阻塞题目主业务。题目发布成功与向量索引成功应是两个独立状态。**

翻译成人话：**老师发布一道题，绝不能因为 Embedding 接口挂了就发布失败。**
这是设计的核心，也是你写代码时的第一原则。

### 5.4 验收标准（自己测，也要给老师看）

任务书阶段一的验收标准，把它变成你的自测清单：

- [ ] 现有符合准入条件的题目都能批量进索引
- [ ] **重复执行不产生重复向量记录**（幂等）
- [ ] **修改题面后，旧索引不再作为最新结果返回**
- [ ] **私有、归档、删除的题目不会出现在学生结果里**（权限隔离）
- [ ] **Embedding 服务异常时题库功能仍然可用**（降级）
- [ ] 有成功/失败/跳过统计和耗时日志

> 🎓 **这 5 条里,第 2、3、4、5 条是"工程质量"考点，不是"功能"考点。**
> 新手最容易只做第 1 条然后说"我做完了"。老师要看的正是后面四条。
